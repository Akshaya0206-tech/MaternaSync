HOW TO READ THIS
  This file lists everything that changed on 26 Oct 2026, in the order of the menus: first
  the PATIENT tabs, then the CAREGIVER tabs, then the DOCTOR tabs, then the assistant and
  backend, the database, hosting, checks, files and the open items. It restates the ground of
  team-update-changes-2.txt (sections 1-11 there) tab by tab, so you can find a change by
  the screen it is on. Nothing here is a new idea: every item exists in the app now.
  NEW / CHANGED / FIXED / REMOVED / UNCHANGED mark what happened to each item. "Tab" is a
  sidebar item, "card" is a box on a page.
  All of it is committed (last commit d814ddb, 26 Oct 23:10). The live copy on Vercel and
  Render is OLDER: it was redeployed on 26 Oct from commit bfe9358, before most of this (see
  "Hosting").

BEFORE YOU PULL / RUN
  1. No new library is needed (backend or front end).
  2. START THE API AGAIN. The old API does not send the new data, so the new buttons stay
     hidden until it is restarted (for example "Show this to the hospital" on Emergency
     help, the Today card on My Care). The new columns and tables are added automatically
     at start-up; nothing is deleted. See "Database".
  3. Start-up also gives the demo records plain titles and kinds (My Records) and fixes
     older databases the same way. Uploaded files are never touched.
  4. Demo logins (all synthetic data), unchanged:
       Patient    sarah.jenkins@maternasync.app   SarahDemo123!
       Doctor     demo@maternasync.app            MaternaDemo123!
       Caregiver  ravi.jenkins@maternasync.app    RaviDemo123!
     The seeded demo accounts cannot be closed and their password cannot be changed.
  5. To see the offline behaviour (installable app, opening with no signal) use the BUILT
     site (npm run build, then npm run preview). It is switched off in npm run dev.

THE BIG CHANGES IN ONE GLANCE
-------------------------------------------------------------------------------------
  1. PATIENT My Care has a Today card; the next appointment no longer shows a visit that
     has already passed.
  2. PATIENT Daily Check-in works with no signal (kept on the phone, sent later, never
     saved twice), checks typing mistakes, prints a list of her entries, and the
     step-by-step version can be carried on after an interruption.
  3. PATIENT Appointments and My Care Plan no longer overlap: visits and requests are on
     Appointments, reminders and instructions on My Care Plan. Add to calendar (Google
     Calendar link and a calendar file with alerts). Change/cancel REQUESTS for a visit.
  4. PATIENT Emergency help: a large-print "Show this to the hospital" card, hospitals the
     clinic recommends, the numbers with no signal, a one-tap call to her emergency contact.
  5. PATIENT My Records: readable titles, kind chips, search, camera photos combined into
     one PDF. My Questions: attachments, follow-ups, new status words.
  6. PATIENT Profile: change password, sign out other devices, download all my data, close
     my account (a request: the record is not deleted automatically).
  7. PATIENT Updates (sidebar dots, links), Sharing & Consent ("Who can see or get what",
     message preview), My Journey (what the words mean), Care Companion and References
     (four new topics, favourites, "reviewed by your clinic").
  8. DOCTOR: three new cards/tabs (Clinical Settings clinic details, Care Assistant usual
     reply time, References "Patient information") and Patient Questions shows files and
     follow-ups. Earlier today: five tabs on References (About Website), the trusted-people
     features, the obstetric layout and words, questions always go to the doctor.
  9. CAREGIVER: a Reminders tab, the doctor's visit checklist, a request from the doctor to
     help with check-ins.
 10. Wording: questions and check-ins go to the DOCTOR (not "care team"); developer-only
     wording was removed from the screens.

AI CARE ASSISTANT AND BACKEND
=====================================================================================
  Question routing: a routine question is assigned to the doctor too (the suggested reply
  stays a proposal the doctor approves; a withdrawn reply returns the question to the doctor's
  list). Missed check-ins: the helper the doctor named is reminded first; others from the
  third reminder. A trusted person's due-reminder note never contains a name.
  Sessions: every sign-in token carries a per-user version (users.token_version); changing
  the password, "sign out other devices" and closing the account raise it. Tokens made
  before the column existed count as version 0, so the upgrade signs nobody out.
  Account closing: marks the account closed, signs out everywhere, removes trusted people's
  access and WhatsApp permissions, refuses sign-in, writes an audit log and creates a doctor
  task. The seeded demo accounts are refused.
  Notifications: the Updates link and the sidebar dot of each note come from
  backend/app/update_links.py; fixed texts are in four languages (server_text.py).
  Glossary (plain_language.py): GCT, NT scan, PROM, PPROM, FGR/IUGR, CPD, PPH, G/P/L/A, and
  now NST, GDMA1/2, EFW, NIPT/NIPS, MFM, CRL, AFI, Doppler, Trisomy, Fetal fraction, Fundal
  height (four languages each).
  Safety rules kept: the woman owns every trusted-person permission; a doctor cannot widen it
  or see invite codes; every release, request, answer, tick and download is audit-logged;
  nothing is written by a model; the app gives no diagnosis, advice or risk score.

  New endpoints (all need sign-in)
    GET  /api/v2/patient/dashboard?tz_offset=     (now also the Today card data)
    POST /api/v2/continuity/episodes/{id}/logs    (accepts clientRef: never saved twice)
    GET  /api/v2/patient/updates/unread-summary, POST .../updates/mark-read
    GET  /api/v2/patient/consent-preview
    POST /api/v2/patient/questions/{id}/attachments, GET /api/v2/patient/questions-info
    GET/PUT /api/v2/assistant/reply-time
    POST/DELETE /api/v2/patient/appointments/{id}/change-request
    GET  /api/v2/patient/my-data (zip), POST /api/v2/patient/close-account
    POST /api/auth/change-password, POST /api/auth/sign-out-other-devices (any role)
    GET/PUT/POST/PATCH/DELETE /api/v2/clinic/emergency[...] (doctor)
    GET  /api/v2/patient/reference-reviews; GET/PUT/DELETE /api/v2/doctor/reference-reviews
    GET/PUT /api/v2/patient/caregivers/visit-prep; /api/v2/caregiver/{link}/visit-prep,
    /checkin-helper, /reminders; for a doctor /api/v2/continuity/episodes/{id}/trusted-people,
    /checkin-helper, /visit-prep

KNOWN GAPS AND OPEN ITEMS
=====================================================================================
  - All Hindi, Tamil and Telugu text written today (about 180 patient texts and three doctor
    dictionaries) needs a native speaker's review. The four new References topics need a
    CLINICIAN's review before they are trusted.
  - The urgent warning-word list is unchanged; clinician-review-urgent-warning-signs.txt
    holds the four candidates for a clinician to decide.
  - Calendar: a web page cannot add to Google Calendar silently (needs Google sign-in in a
    Google Cloud project) or set a clock-app alarm. The button opens Google Calendar with
    the entry filled in; the file sets calendar alerts. Google's link cannot carry an alert.
  - Closing an account does not delete the record, by design; the clinic follows its policy.
    There is no way in the app to reopen a closed account.
  - The data download lists its tables explicitly: a new table must be added to
    backend/app/account_service.py.
  - A withdrawn visit-change request does not remove an assistant proposal already waiting.
  - Offline: only Daily Check-in, Step-by-step and Emergency help are made to work without
    a signal. Check-ins kept on a shared phone stay there until sent or removed.
  - Patient pages that still say "care team": the Emergency help sentence, My Records, Journey.
  - "Show this to the hospital" shows only what has been entered: a fresh database has no
    clinic phone or recommended hospitals until a doctor adds them.
  - WhatsApp (simulated), real hospital systems and the Claude provider were not run live.
  - Not built from the idea lists: showing the doctor a trusted person's transport answer,
    asking a trusted person to upload reports, "read this together" confirmations, a
    practical-help log, and a doctor-to-trusted-person message thread.
