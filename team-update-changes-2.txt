  "card" is a box on a page.

BEFORE YOU PULL / RUN
  1. Backend:   backend/venv/Scripts/python.exe -m pip install -r backend/requirements.txt
     (no new library is needed; the meaning search uses onnxruntime, which the speech-to-text
     library already installs)
  2. START THE API AGAIN. The old API does not know the new permission or the new endpoints,
     so "Reminders" will not appear in the caregiver menu until it is restarted.
     New database tables (visit_prep_items, checkin_helpers) are created automatically.
  3. Optional, for the meaning search on the doctor's References tab (see section 6):
        cd backend
        python fetch_search_model.py        (downloads about 135 MB, once)
        python build_semantic_index.py      (about 4 minutes the first time)
     Without these the search works by words exactly as before. MATERNASYNC_SEMANTIC_SEARCH=off
     switches the meaning search off even when the model is installed.
  4. Optional, for the four FIGO papers (section 6):  python fetch_reference_documents.py
     If Europe PMC refuses the script (HTTP 403), the script prints the link: open it in a
     browser, save the PDF into backend/reference_documents/ and run the script again.
  5. Demo logins (all synthetic data), unchanged:
       Patient    sarah.jenkins@maternasync.app   SarahDemo123!
       Doctor     demo@maternasync.app            MaternaDemo123!
       Caregiver  ravi.jenkins@maternasync.app    RaviDemo123!
     Ravi's demo permissions now also include the new "reminders" permission.

THE BIG CHANGES IN ONE GLANCE
-------------------------------------------------------------------------------------
  1. DOCTOR menu is shorter: 17 tabs -> 13. Four tabs were folded into others as sub-tabs.
  2. DOCTOR References search now also searches BY MEANING: a question in Hindi, Tamil or
     Telugu finds the English passage. Four FIGO papers were added. Passages are cleaner.
  3. PATIENT Profile tab redesigned: five coloured cards and four animations.
  4. Questions and check-ins now go to the DOCTOR, in wording and in fact: every question is
     assigned to the doctor (before, a routine question was only a suggested reply).
  5. FOUR new doctor <-> trusted person features: visit checklist, check-in helper,
     reminders for the trusted person, and the doctor's "Trusted people" card.
  6. Hosting: the site is live on Vercel and the API on a free Render plan (the live copy is
     the old version). render.yaml moved to deploy/.
  7. OBSTETRIC ADDITIONS (after the commit above): a first-visit history layout for the
     doctor, seven more words explained in plain language, and a patient card "Before your
     first visit". See section 7.
  8. ABOUT WEBSITE: a new fourth tab on the doctor's References page, a twelve-section guide
     for a doctor who is new to the app. See section 8.
  9. Small fixes: phone sidebar edge strip, caregiver banner under the menu button,
     amber badge contrast.

  Fixed texts
  [NEW]     Eight new fixed messages in four languages (server_text.py): checklist added
            (to her, to the trusted person), helper asked (to her, to the person), request
            withdrawn, person said yes, person said no, reminder due for the trusted person.
  [CHANGED] The companion's fixed replies, the missed-check-in reminder to her, and the notes
            "<name> asked your doctor a question / to get in touch" say doctor.

  [NEW]     Permission "reminders" (off by default) next to the five existing ones.
  [NEW]     Tables visit_prep_items and checkin_helpers (created automatically).
  [NEW]     Endpoints: GET/PUT /api/v2/patient/caregivers/visit-prep, GET/PUT

            GET /api/v2/caregiver/{link}/reminders, and for a doctor
            /api/v2/continuity/episodes/{id}/trusted-people, /checkin-helper, /visit-prep.

    - The woman owns every permission. A doctor cannot widen what she chose, cannot see

    - A trusted person's every request is re-checked for link, owner, end date and permission.

6. REFERENCE LIBRARY SEARCH BY MEANING (doctor: References tab -> Reference Library)
=====================================================================================
  [NEW]     backend/app/semantic_search.py. A small multilingual model (multilingual-e5-small,
            MIT licence) turns every passage and every question into numbers; text that
            means the same is "close", in any language it knows. Used only to RANK results.
            It never writes, translates or summarises: a result is still the document's own
            sentence with its page number. If the model is not installed the search works by
            words as before.
  [NEW]     Scripts (run from backend/): fetch_search_model.py (download once),
            build_semantic_index.py (index the passages), evaluate_semantic_search.py
            (our own check of how many test questions the library answers: references
            17 -> 54 of 72, passages 8 -> 22 of 36, in the last measurement).
  [NEW]     MATERNASYNC_SEMANTIC_SEARCH = auto (default) or off, in .env.example and README
            ("Searching by meaning").
  [CHANGED] Passages are cut into short paragraphs (about 700 letters, never past 1,400, never
            across two pages, so the page number stays exact). PDFs stored the old way are
            split again at start-up. Soft hyphens are removed.
  [CHANGED] Bibliographies, licence pages and journal headers are recognised and left out of
            results.
  [CHANGED] A passage match now needs 70% of the question's words (was half), because a
            passage is a short paragraph.
  [CHANGED] Four FIGO papers (PMC9290930, PMC9313855, PMC12640178, PMC12640184) are kept as
            PDFs for passage search (open access, CC BY or CC BY-NC, with attribution).
            fetch_reference_documents.py retries three times and explains what to do if the
            publisher refuses scripts.
  [NOT ON THE FREE HOST] The model needs about 135 MB and 300 MB of memory, so it is off on
            the free Render plan.
