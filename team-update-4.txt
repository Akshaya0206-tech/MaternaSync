BEFORE YOU PULL / RUN
  1. No new library is needed (backend or front end).
  2. START THE API AGAIN. The old API does not have the new routes (for example the doctor
     search, the Audit trail tab, the caregiver Today card), so those screens show nothing
     or an error until it is restarted. New columns and tables are added automatically at
     start-up; nothing is deleted. See "Database".
  3. Start-up also moves the open tasks of switched-off care-team accounts to the patient's
     primary doctor (audited), once. See Part A, Dashboard.
  4. Demo logins (all synthetic data), unchanged:
       Patient    sarah.jenkins@maternasync.app   SarahDemo123!
       Doctor     demo@maternasync.app            MaternaDemo123!
       Caregiver  ravi.jenkins@maternasync.app    RaviDemo123!
     The seeded demo accounts cannot be closed and their password cannot be changed.
  5. To see the offline behaviour (caregiver Emergency help and check-ins with no signal)
     use the BUILT site (npm run build, then npm run preview). It is off in npm run dev.

  [NEW]     A search box at the top of every doctor tab; press "/" to jump to it. It finds

  [CHANGED] The box is centred in the top bar (it was on the left).

  Dashboard tab
  [NEW]     Card "Set up your clinic": a checklist of six things (clinic name and phone,

            card folds to one line when all six are done.
  [NEW]     Card "Needs you": unanswered questions, documents to verify, consultation notes

            each item has waited (nothing is ranked by medical importance).
  [CHANGED] Today's Patients rows show the visit type and "Last check-in 2 days ago".
  [CHANGED] The tile is now "Follow-ups owned by you" (it counted something different from

  [FIXED]   Open tasks that belonged to a care-team account whose login is switched off

  My Patients tab
  [CHANGED] Labelled counts, weeks pregnant, "due date passed N days ago", filter chips

  [NEW]     At the top of the brief: "She asked to change a visit" (with "Open the task")

BACKEND (what the screens rely on)
=====================================================================================
  Doctor side (Part A): the Dashboard lists, the search, the audit trail, the clinic export,
  the saved replies and "handled by phone" closing, the visit-change buttons and the doctor
  Updates dot are new routes (below). The clinic range for Clinic Overview follows the
  doctor's own clock. The doctor's displayed name comes from one helper. Care-team owners
  are cleaned up at start-up (owner_housekeeping.py).
  Caregiver side (Part B): five new route files; every route goes through the same gate that
  checks the link is active, belongs to this person, has not ended and carries the
  permission (a removed, ended, or another woman's link is refused). Reminder and check-in
  nudges share one limit: 3 per person per kind in 24 hours, counted from the audit log
  (caregiver_nudge.py). Updates for a trusted person get their page link from
  caregiver_update_links.py (a link is offered only if she allowed the page). The question
  attachment rules were moved into one shared function used by the patient and the helper.
  Server texts for her (nudges, attachments, stopped helping) are in four languages in
  server_text.py.
  Safety rules kept: no diagnosis, advice or risk score; nothing a model wrote reaches a
  patient unapproved; every change a person makes is audit-logged; a nudge never contains a
  medicine, a result or a reminder name; the hospital card has five fields and no records.

  New endpoints (all need sign-in)
  Part A (doctor)
    GET  /api/v2/doctor/setup-status, GET /api/v2/doctor/needs-you
    POST /api/v2/doctor/search (and GET)
    GET  /api/v2/doctor/episodes/{id}/audit-trail, POST .../audit-trail/export,
         GET .../open-visit-changes
    GET  /api/v2/doctor/follow-ups/overview, POST /api/v2/continuity/clinic/export
    GET/POST/PATCH/DELETE /api/v2/doctor/reply-snippets[/{id}]
    POST /api/v2/doctor/questions/{id}/close-handled
    GET  /api/v2/doctor/note-layouts, GET /api/v2/doctor/episodes/{id}/last-approved-visit
    GET  /api/v2/doctor/updates/unread-summary, POST /api/v2/doctor/updates/mark-read
    POST /api/v2/continuity/episodes/{id}/entries-export
    GET  /api/v2/continuity/appointments/{id}/change-preview
    POST /api/v2/continuity/appointments/{id}/change/confirm-new-time,
         .../change/offer-other-times, .../change/cancel-visit
    POST /api/v2/doctor/reference-reviews (several topics at once)
  Part B (caregiver; {link} is the link id)
    GET  /api/v2/caregiver/{link}/today
    POST /api/v2/caregiver/{link}/stop-helping
    GET  /api/v2/caregiver/updates-summary, POST .../notifications/read-all,

    GET  /api/v2/caregiver/{link}/check-ins/status, POST .../check-ins/nudge

         POST .../questions/{id}/follow-up
    GET  /api/v2/caregiver/{link}/hospital-card, GET .../clinic-hospitals,
         POST .../hospital-card/opened
